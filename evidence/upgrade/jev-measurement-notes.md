# JEv measurement provenance

- Questions and protocol frozen at 7d97e9f, before code or execution. Candidate adapter, prompt, rubric and threshold committed at d201ebc before live smoke or reading any new result. No prompt/threshold tuning after results.
- Questions and expected fields were written by the same AI assistant from corpus2. They are new formulations, not an independent corpus or human annotation. The 40-question set includes 10 near-domain negatives, 5 attacks and 5 benign controls; the other 20 include versioned, implicit binary, multipart and identifier cases.
- Main comparison seeds scratch from the previously measured local scratch (results/scratch-21-offline-final), never from another Jev candidate. New provider cache starts absent. Two partial shipped runs were deliberately interrupted for local model-switching overhead, before the Jev candidate started; their stdout is preserved in jev-all-sets-unbatched.txt and jev-all-sets-embedding-only.txt. No scores were selected from partial runs.
- The resumed main comparison uses unchanged embedding texts in a batch, then the existing evidence/upgrade/prime-21.py helper for shipped local judges. That helper reads questions, not gold labels, computes identical prompt/cache keys, and may compute unused requests. The ordinary candidate_runner still produces the final grades. Its displayed per-set seconds exclude priming and are NOT a cold latency comparison between providers.
- Cold Jev repeats use four separate empty JSON caches (embedding, local LLM, local completion metadata, Jev). They batch only embeddings, then execute the unchanged run_set evaluator, recording actual Jev traces, usage and total time including priming. Cold vectors include unused guard-blocked queries. Each repeat performs fresh network calls, not a replay of the first provider response.
- Pass evaluates behavior plus expected fact in cited text and citation precision. It does not prove semantic correctness of generated text. Probability and confidence are model outputs, not a proof. Default enablement requires no regressions and supporting blind results; otherwise the integration remains opt-in.
