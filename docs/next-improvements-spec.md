# E1–E5: naredna poboljšanja

Polazni commit: 53fbc25. Originalni eval i metric kod, korpus, istorijski keševi i M5 ostaju netaknuti. Pet zasebnih celina po korisnikovom zahtevu „reši sve”.

1. E1: konzervativna provera obuhvata, granica i modalnosti tvrdnje prema njenom citatu. Po osobi/timu, najviše/najmanje, dozvola/obaveza. Pozitivne kontrole sprečavaju odbacivanje podržanih iskaza. Heuristika ne dokazuje semantičku tačnost. Prihvatiti bez novih originalnih PASS regresija.
2. E2: zamrznuti novi dvojezični kandidatski skup pre implementacije, zabeležiti SHA-256 i profil/režim svakog merenja. Skup autora asistenta nije nezavisno ljudski potvrđen niti slepi dokaz generalizacije. Alat za ljudsko odobrenje mora odbiti praznog recenzenta/nepotpune ocene. Pitanja ne koristiti za podešavanje pragova. Izveštaj jasno razdvaja ekstraktivnu proveru, keš i sveže model pozive; dva jezika iste činjenice nisu dve nezavisne činjenice.
3. E3: automatski ili eksplicitni sr/en izbor; srpska latinica i ćirilica. Dvojezični prateći odlomci sa SHA-256 originala, istim ID/statusom/verzijom; nema izmišljanja ljudske potvrde prevoda. Srpski ekstraktivni odgovori rade bez modela. Napredna pretraga može koristiti lokalni multilingual embedding; srpski odgovor je izvorni prevedeni odlomak, jasno označen. Ako prevod ne odgovara originalu po hashu, odbiti srpsku obradu umesto tihog korišćenja zastarelog teksta. Engleski tok i originalni citati ostaju isti.
4. E4: ograničen lokalni red pozadinskih poslova, statusi queued/running/cancelling/completed/cancelled/failed, stvarne faze i trajanje, kooperativno otkazivanje između koraka i posle aktivnog model poziva; bez prikaza izmišljenih procenata. Jedan worker zbog globalne konfiguracije. Dokumenti/status dostupni tokom generisanja. Rok obrade, TTL i ograničen broj poslova. Nezavršeni posao posle restarta nije trajno sačuvan. Novi web upiti koriste izdvojene runtime kopije istorijskog keša.
5. E5: istorija v2 sa migracijom v1, spajanjem po ID razgovora i pitanja, brisanjima i eksplicitnim undo; Web Locks serijalizuje read/merge/write, storage događaji osvežavaju druge tabove. Paralelni različiti upiti u istom razgovoru moraju oba opstati; brisanje se ne sme neprimetno poništiti zastarelim tabom. Bez Web Locks ostaje upozorenje i izvoz. Bez slanja istorije modelu.

Provera: negativni testovi pre implementacije; pytest; frontend unit/build/format; Playwright stvarni API i izolovani tabovi, mobilni prikaz, WCAG i konzola; originalna četiri skupa u replay režimu pre/posle; kandidatski skup zamrznut pre izmena. Izveštavati preostale padove, novu heurističku prirodu, nedostajuću ljudsku potvrdu i granice otkazivanja. Ne preuzimati nove modele/pakete. Postojeći lokalni modeli mogu se pokrenuti za zabeležene probe.
